# Web App Implementation Plan (Phase 1)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the approved "workshop board" prototype into a real product on Cloudflare Pages: story landing + an app where a team opens a chest, issues invoices, gets paid through Arc Memo, votes, and receives payouts — all against the live mainnet factory.

**Architecture:** Vite + React + TypeScript (strict) single-page app. Landing is the prototype ported 1:1 (same DOM/CSS/GSAP + verlet canvas) as a React route with lifecycle cleanup. App routes read chain state with viem public client and write with wagmi (injected wallet, Arc chain 5042). No backend in Phase 1: everything is on-chain reads + event logs.

**Tech Stack:** Bun, Vite 6, React 19, TypeScript strict, wagmi 2 + viem 2, @tanstack/react-query, react-router 7, GSAP 3 (+ScrollTrigger), vite-plugin-pwa, Cloudflare Pages (wrangler).

**Spec:** `docs/superpowers/specs/2026-10-09-collective-treasury-design.md` §7. Contracts: `deployments/arc-mainnet.json`, ABI from `contracts/out`.

## Global Constraints

- Visual language = `design/mockups/c-workshop-board` (cork, paper cards, pins, red string; Cabinet Grotesk / Satoshi / Gambarino / JetBrains Mono; DESIGN.md motion tokens, ≤5 easings). No new design directions.
- User-facing copy: English primary (global jury), Turkish toggle later; plain words (chest, reserve, share, vote) — no jargon (bps, epoch, attribution) in UI.
- Amounts: USDC 6 decimals everywhere; never use native 18-dec balances.
- Payments go through Memo (`memo(target,data,memoId,memoData)`) when the payer is an EOA; approve exactly the invoice amount (review M-note).
- Wallet: injected (MetaMask) with Arc chain add/switch prompt. Read-only browsing works without a wallet.
- PWA manifest + app-shell cache. Hosting Cloudflare Pages.
- `prefers-reduced-motion` respected; mobile 375px no horizontal scroll.

## Review Focus

1. Wrong chain connected → every write button shows "Switch to Arc" instead of failing.
2. Payer has less USDC than the invoice → pay button disabled with balance shown, no failed tx.
3. Invoice already paid/cancelled → pay page shows status, no pay button.
4. User not a member → dashboard is read-only (no vote/propose/invoice buttons).
5. RPC rate limit (Arc public RPC returns -32005) → reads retry with backoff, UI shows stale data not a crash.

- [ ] Arc chain: id 5042, name Arc, native currency USDC (18), rpc `https://rpc.mainnet.arc.io`, explorer `https://explorer.arc.io`. viem `http()` transport with `retryCount: 5, retryDelay: 400`.

### Task 4: Open a chest

**Files:** `web/src/app/NewChest.tsx`.

- [ ] Form: name, members (addresses, min 1, max 50, includes connected wallet by default), reserve % and target, agent address (optional), period (1h–366d; presets week/month), vote rules shown in plain words ("more than half of members", "wait at least 1 hour").

### Task 5: Chest dashboard

**Files:** `web/src/app/Chest.tsx`, `web/src/app/useChest.ts` (reads: name, members, rules, reserve, pool, unattributed, period, periodStart, creditors+credit, owed for me, proposals; events: InvoiceCreated/Paid, Paid, Distributed, Proposed/Voted/Executed).

- [ ] Votes panel: open proposals with votes/needed, executable-at countdown, vote/unvote/execute/cancel; propose forms for add/remove member, change rules, allow payee, release reserve.
- [ ] Claim button when `owed(me) > 0`.
- [ ] Review Focus 4: non-members see read-only.
